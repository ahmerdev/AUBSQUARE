## Checked by hand in a real browser (Chromium via Playwright, desktop 1440 px and phone 390 px)
* Dashboard redesign (“Soft Pill”): light and dark mode on dashboard, lists, forms, details, analytics, leads, users and sign-in; Light/Dark switch persists across pages; mobile menu sheet; spotlight search (`/`); charts recolour when the theme changes; no JavaScript errors.
* Fixed side menu: stays in place while the page scrolls, only its page list scrolls, keeps its scroll position between pages, collapses to icons with tooltips, hidden on phones (menu sheet instead). Form pages: numbered sections collapse/expand, “On this page” highlights the section being read, “Unsaved changes” indicator, toggle switches, Save works without an unsaved-changes prompt, sticky save bar at tablet/phone widths.
* Logo flow end to end: upload in the media library → set in Website settings → the dashboard header, sign-in page, website header, footer and browser-tab icon all show the new logo; an already-open website tab picks it up when you come back to it (within ~20 s) without a manual reload. SVG logos are not accepted by the uploader on purpose (use PNG, WebP or JPG).
* Dashboard pages render, no horizontal scrolling, no console errors (earlier phase).
* Public site against the live API: Home, Services, Service detail, Portfolio (+detail), Case studies (+detail), Blog (+detail), About, Contact, 404 – no horizontal overflow, no JavaScript errors.
* End-to-end: quote form → lead appears in the database as *New*; client-side validation; blog search; newsletter sign-up; comment submitted → stored as *Pending* (not shown publicly); chat widget → conversation stored and a rule-based reply returned.

* Branding page in a real browser: heading/body Google Font pickers (search, category tabs, live sample), live preview in an iframe with Desktop / Tablet / Mobile / full-screen, unsaved changes visible in the preview (font, logo, name, header option), saved fonts reach the served website HTML, the bootstrap API and the dashboard; the website header shows the logo only. Because the sandbox cannot reach fonts.googleapis.com, the fallback font stacks were verified there – **check once in your own browser that the real Google fonts render**.
* Media library in a real browser: upload (drag & drop / browse), grid and list views, search/filter/sort, copy link, single download, bulk select → ZIP download and bulk delete, details dialog (name, URL, size, dimensions, usage) with edit, delete protection for files in use.

## NOT tested (be aware)
* **Outbound Sales – live services**: real SMTP/IMAP sending and reply detection, live OpenStreetMap (Nominatim/Overpass) discovery, live Gemini calls. Discovery and AI were tested with stubs; OSM was not reachable from the build sandbox. The audit covers the home page and up to 6 internal links only, not full-site crawling or speed tests.
* **Ads** are tracking/cost-per-lead records only – no live Google/Meta connection exists.
* **Brand colours** are saved and previewed in the dashboard only; the 3D website keeps its own colour scheme (they are not applied to it).
* **Live e-mail providers** – real Gmail / Google Workspace / Outlook / Microsoft 365 SMTP and IMAP. Only a local SMTP server and sample messages were used. Provider rules (app passwords, OAuth requirements, 2FA) can still block a login; test with *Send test email* after configuring.
* **Google Ads / Meta Ads / GA / Search Console APIs** – the ads and marketing modules store *local records* only; no live ad-platform connection exists, and no numbers are invented. Dashboard analytics are your own site’s page-views.
* **AI chat provider** – the code path is present, but only the key-protection and failure-fallback behaviour was tested with a stubbed HTTP layer; no real provider call was ever made.
* **PostgreSQL** – developed and tested on SQLite. The settings and migrations are standard Django, but run the test-suite once against PostgreSQL on your server (`DB_ENGINE=postgres python manage.py test apps`).
* **Production hosting** – gunicorn/nginx/HTTPS/HSTS/cron were not exercised in this environment.
* **Browsers/devices** other than headless Chromium (Safari/iOS, Firefox, real phones). Images from external sites (Unsplash) were blocked in the test sandbox, so image-heavy visuals were not visually verified.
* **Load/performance testing and an external security audit.**
* The long numbered acceptance list in the brief was tested through the suites above; compare it line-by-line with this report before you sign off.
